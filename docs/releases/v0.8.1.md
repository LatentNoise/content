0.8.0 gave the engine a sign-in door and the three UIs could not walk through
it. This release finishes the job: a signed-in visitor is recognised by every
surface, a refused one gets a page that explains rather than an error, and a
sign-in lands somewhere useful instead of on the API documentation.

**If you self-host, nothing changes.** No cookie is sent, none is needed, and
the same tests prove a surface still reaches the single local user with no
credential at all.

## The surfaces carry the visitor, without ever naming them

The UIs are Streamlit applications, which means they run on a **server**: the
browser talks to Studio, and Studio talks to the engine from its own process.
The visitor's session cookie only ever reaches the first hop. Under
`CONTENT_AUTH_MODE=token`, a signed-in person therefore faced a surface that
was, to the engine, anonymous — and every call answered 401.

The fix is one sentence: **the surface replays the cookie it was given, and
never declares who the visitor is**
([ADR 0034](https://github.com/LatentNoise/content/blob/main/docs/architecture-decisions/0034-a-server-side-surface-relays-it-does-not-declare.md)).
The alternative — a service credential per UI plus a field naming whom it acts
for — works on day one and destroys what ADR 0030 exists to protect. A surface
that can name any user is a surface whose compromise is every account.

The dangerous part was never how the credential travels, but where it lives.
All three UIs cache one client for the whole process:

```python
@st.cache_resource
def get_client(base_url): return ContentClient(base_url)
```

That object is shared by **every visitor of that process**. Attaching an
identity to it would have made one person's session the next visitor's —
silently, and only under concurrent use, which is the worst way to find out.

So the SDK gained `headers_provider`, a callable invoked on **every** request:

```python
ContentClient(base_url, headers_provider=lambda: streamlit_visitor_headers(st.context))
```

The cached client stays shared and stays correct, because it holds no identity
at all and asks for one at the moment it is used. A provider that raises yields
no headers rather than an error — an absent identity is a valid state, and it
is precisely the self-hosted one.

An integration test signs two people in for real and sends both through one
cached client; a UI test asserts all three surfaces build their client with a
provider, so a fourth cannot silently skip it.

## A refused visitor gets a page, not a warning bar

A surface the engine refuses now stops and shows what is being asked for, what
happens next, and one button — plus a note that one session covers all four
surfaces, so someone already signed in elsewhere only needs to reload.

It is a block and not a redirect, on purpose. Streamlit renders inside an
isolated frame where an automatic redirect is unreliable, and one that fires on
a refusal it misread traps the visitor in a loop they cannot leave.

401 and 403 are told apart: signed in but not allowed is a different message,
and returning someone to a form they already filled would be wrong.

## A sign-in lands somewhere useful

Following a link from a mail dropped the visitor on the engine, which serves
API documentation and welcomes nobody.

`CONTENT_SIGN_IN_DEFAULT_TARGET` names the landing page for a link that carried
no destination of its own. A link that names one still wins, and the engine
falls back to itself when nothing is configured, so no deployment changes
behaviour without being told to.

The configured default is checked against the same allowlist as any other
destination, and ignored with a log line when it is not on it. A default that
skipped that check would be the one redirect nobody validates — the exact shape
of an open redirect a reviewer never finds.

## Also

- The confirmation page said an account exists *to* an address. It exists
  *for* one. A visible mistake on a page people read at the one moment they
  are waiting for something to arrive.

## Upgrading

Nothing to do, and nothing changes until you ask for it. `CONTENT_AUTH_MODE`
still defaults to `none`.

Turning the hosted mode on now needs, in order: a reachable mailer
(ADR 0031), `CONTENT_ALLOWED_REDIRECT_ORIGINS` listing your surfaces,
`CONTENT_SESSION_COOKIE_DOMAIN` set to the parent domain they share, and
optionally `CONTENT_SIGN_IN_DEFAULT_TARGET`. Then `CONTENT_AUTH_MODE=token`.
