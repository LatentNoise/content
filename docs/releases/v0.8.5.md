## Licence: Content is source-available, and says so

- **Self-hosting is unaffected, and free.** Running Content at home, on your own
  machine, or inside your organisation — modified or not — is a Permitted
  Purpose. You are not required to publish your changes, and you do not owe
  anyone anything.
- **The one reserved case** is offering Content, or something substantially
  similar built from it, as a competing commercial product or service.
- **Every version becomes Apache 2.0 two years after it is published.** That
  promise is inside the licence and cannot be withdrawn.
- **Versions up to and including 0.8.4 remain AGPL-3.0-or-later, permanently.**
  Nothing was relicensed retroactively, and nothing can be.
- Content should no longer be called open source; *source-available* and
  *delayed open source* are the accurate words, and the documentation now uses
  them everywhere.

Why: the hosted engine and the agent door are the products, and the AGPL
reserved nothing against a competitor selling exactly those. The reasoning is in
[ADR 0040](https://github.com/LatentNoise/content/blob/main/docs/architecture-decisions/0040-the-licence-becomes-fsl.md),
and the practical summary in
[COMMERCIAL.md](https://github.com/LatentNoise/content/blob/main/COMMERCIAL.md).

`CONTENT_SOURCE_URL`, `/api/v1/system → source_url` and the footer the surfaces
render all keep every line of behaviour: the AGPL required that offer, and a
source-available project that hides its source is worth less than one that shows
it. An operator running a fork SHOULD still point the setting at their own
source — not to discharge a duty, but because otherwise the link tells their
users something untrue.

Standalone HomeTube is a separate project and stays AGPL-3.0-or-later.

## HomeTube speaks French

The interface has an English and a French catalogue, and the sections a legacy
HomeTube user already knows keep legacy's own wording — « Publicité et
Sponsors », « Coupes », « Qualité Vidéo », « Intégrations Vidéo », « Gestion des
Cookies », « Options Avancées ». Migrating should mean recognising the page, not
relearning it.

The language is chosen in three places, in this order: `?lang=fr` in the address
(a link can carry it), the picker in the sidebar, and `CONTENT_UI_LANGUAGE=fr`
for the whole instance — the same gesture legacy HomeTube spells `UI_LANGUAGE`.
An installation that configures nothing renders exactly the English it rendered
before.

It is resolved per visitor rather than once per process: one server renders for
everybody, so a cached language would make the first visitor's choice
everyone's.

Studio and Content Admin are not translated yet; the layer they would use is
already shared.

## HomeTube remembers what you asked for

Paste a URL you have asked for before and HomeTube says so — *"You asked for
this on 20 September"* — and fills the form back in: the destination folder, the
outputs, the languages, the quality, the cut, the credential, the extra
arguments.

It is keyed on the **source**, not the address: a share link, a link carrying a
playlist parameter and a link with a timestamp all resolve to the same video, so
the memory answers for all three. A folder that no longer exists is proposed as
a new folder rather than dropped silently, because a prefill that quietly
changes where a file lands is worse than none.

The memory is per account and per source, and it holds one entry — the last
request, overwritten. `GET /api/v1/last-request?source_ref=…` is the route, and
it answers only for the account that asked
([ADR 0039](https://github.com/LatentNoise/content/blob/main/docs/architecture-decisions/0039-a-persons-last-request-for-a-source.md)).

## A second sign-in link arrives, and arrives findable

Asking for another link appeared to send nothing. Every mail was sent, and every
one landed in the same conversation: they all shared the subject "Your Content
sign-in link", and mail clients group by sender and subject, so each new link
folded under the first — already read, often archived.

- **Each mail is its own conversation now.** The subject ends in a short
  reference, the confirmation page shows the same one — *"its subject ends in
  7KQ3; if you asked more than once, that is the newest"* — and a threading
  header keeps transactional mail apart.
- **The hourly limit counts only unopened links, and defaults to fifteen.** It
  used to count every link issued, so signing in from a second browser spent the
  allowance *by succeeding*. A link that was opened is a person signing in; the
  flood the limit exists for is somebody asking for links to a stranger's inbox,
  and those are never opened.

The answer still says nothing about whether an address has an account: the
reference is made before the limit is consulted.

## Fixed

- **A document could lose its replacement mark.** When a character is in none of
  the available fonts, the renderer draws `U+FFFD`; it only accepted that mark
  if *every* font carried it, which one narrow face in the font path is enough
  to break. On most real machines the engine quietly fell back to `?`.
- **`make extension-zip` reported success without building anything.** Without
  the `zip` binary it printed the archive's name and exited 0 with no archive —
  a release step lying about an asset.
- **The health check's writability test** asserted a premise that root does not
  obey, so it failed on any machine running the suite as root while the engine
  was behaving correctly.
- **The base-image documentation quoted a pin that had not been current since
  0.6.7**, and `deploy/docker-compose.yml` was edited by hand where it is
  generated.

## Under it

The yt-dlp base image is refreshed to the current `2026.08.19` rebuild — same
yt-dlp, patched layers underneath.

[ADR 0041](https://github.com/LatentNoise/content/blob/main/docs/architecture-decisions/0041-the-output-is-the-library-and-there-is-no-cache.md)
is recorded as **proposed**: the output is the person's library and the only home
of a delivered file, with no cache beside it. Nothing in this release implements
it; it is written down so the code that follows has something to be measured
against.

## Upgrading

**One database migration**, applied at startup: a table for the last request per
account and per source. Nothing else changes shape.

`GET /api/v1/last-request` is new; a client that does not know it is unaffected.

If you set `CONTENT_MAGIC_LINK_MAX_PER_HOUR`, your value still applies. If you
did not, the limit moves from five links an hour to fifteen unopened ones.

`CONTENT_UI_LANGUAGE` is new and optional; unset means English.
