A visitor with no session was shown a complete, working product that quietly
did nothing. That is the release: the surfaces now say who you are, say when
you are nobody, and let you stop being either. Around it, retention learned to
keep a job's history while freeing its bytes, and a hosted instance stopped
mixing everyone's finished files into one library.

**If you self-host, upgrading changes nothing you asked for.** Retention stays
off, every quota stays off, your library stays where it is, and nobody is ever
asked to sign in.

## The surfaces never asked who was visiting

A surface boots on routes that carry no owner by design — `/health`,
`/config`, `/system` — because an installation must be able to say it is alive
before it knows who is asking. Every owner-scoped call then sits inside a block
that degrades politely, a dash instead of a job list, because one slow endpoint
must not take the page down. Each habit is right on its own. Together they
meant the refusal never arrived anywhere it could be acted on: delete your
cookie, reload, and Studio came up looking perfectly normal.

Nothing leaked — every owner-scoped call still refused — but a UI that renders
for someone it will not serve is a broken promise.

So the challenge is now **asked, not awaited**: `GET /api/v1/auth/me`, first,
on every run. It is the one route whose answer *is* an identity, so nothing
else can satisfy it. The answer is not cached: a session deleted between two
clicks stops working on the next one.

**The interface still renders.** Someone arriving at a public instance should
see what the product is before being asked for anything. Above it, a banner
says plainly that nothing will run until you sign in, with the button that does
it, and the same button sits in the sidebar where it stays after the banner
scrolls away. It is a button and not a redirect for a reason that is not
preference: Streamlit components render inside an iframe sandboxed without
`allow-top-navigation`, so a script cannot move the browser out of the app at
all.

And signing in finally has its matching verb. The sidebar shows who you are,
with the operator badge when it applies, and **Sign out** beside it. Until now
the only way to end a session was deleting a cookie in browser settings.

### Why no test caught it

The three Streamlit apps talk to `content_sdk.compat.ContentClient`, and four
methods they call — `whoami`, `api_keys`, `create_api_key`, `revoke_api_key` —
existed only on the typed client. Every one of those calls raised
`AttributeError` in production, which is also why the Console's Access tab had
never worked since 0.8.2.

The UI suite passed throughout, because the test double implemented all four.
A fake more capable than the thing it stands for turns a whole suite green over
a broken product, and no behavioural test can catch it: the fake is what the
tests exercise. The new guard rail is mechanical and bidirectional — what the
apps call, what the real client offers, what the fake offers — and the second
direction is the one that would have caught this.

## Retention expires bytes and keeps the history

The sweep used to delete the whole job. It now takes `artifacts/`, `sources/`
and the job's `tmp`, and leaves everything that makes the job answerable: the
row, the steps, the logs, the snapshots, and the artifact rows marked with the
moment their content went. A job's history is a few kilobytes of JSON — 8 KB
measured on a real instance — against a video of hundreds of megabytes.

The API says which of the two happened. `artifact_content_expired` with the
date, rather than the bare "content is gone" it uses for a file it lost:
expired means ask again and it will be produced anew.

The sweep is one indexed query instead of one per owner, bounded to a batch per
pass, and skips jobs whose artifacts are already expired — otherwise it would
walk the same directory on every tick forever. Migration 12 indexes
`jobs(finished_at)`, because that query runs forever and almost always finds
nothing.

## A library each, as soon as people sign in

`CONTENT_DELIVERY_SCOPE` defaulted to `shared`, so an instance that asks people
to sign in put everybody's finished files in the same folders. Worse, a shared
library belongs to nobody: it is counted against no quota and swept by nothing,
so delivery was a way around the storage limit.

The default now derives from the authentication mode, at the same single line
where the storage layout already does. Nobody signs in, one library at the
root, which is what self-hosting keeps and what a media server already reads.
People sign in, a library each inside their own directory. An explicit value
still wins, which is what a household sharing one library sets.

**Operators upgrading a hosted instance:** delivered files move from the
configured library to `<data>/users/<owner>/output`. Existing files are not
touched — no migration reaches into a library — so a media server reading the
old path keeps seeing what is already there and stops seeing new arrivals.
Point it at the new path, or set `CONTENT_DELIVERY_SCOPE=shared` explicitly to
keep the old behaviour.

## `local` is reserved by refusal, not by convention

`local` owns everything a self-hosted instance ever produced, and it is the
operator of its own machine unconditionally. Account ids carry a `usr_` prefix
so a collision cannot happen by accident, but the id reached account creation
as an argument, and a convention is not a guarantee.

Creating an account on `local` now raises. And on an instance where people sign
in, a credential that resolves to `local` is refused at the edge and logged as
an error — so a row saying `local` hands nothing out, whether it came from data
carried over from before sign-in was turned on, from an edited database, or
from a bug upstream. That case is not hypothetical: an instance that ran
self-hosted has `local` all over its jobs.

## What the quota counts

Artifacts, the delivery library and uploads: the results a person asked for,
where they asked for them, and what they put there themselves.

Not `resources`, the raw material the engine keeps so the *next* job need not
fetch it again, and not `tmp` or the job history. Billing a cache nobody
requested would charge for an optimisation and punish the very reuse that makes
the engine cheaper to run. `GET /api/v1/storage` reports every family and
counts three.

## For contributors

Two ways to look at the product before anything is published, both documented
in `docs/development/seeing-it-run.md`:

- `make dev` runs the engine and the three surfaces from the working tree, all
  reloading on save, with sign-in working against no mail server — the link
  goes to the log and the script prints it.
- `make k8s-test` puts the same tree into a second Kubernetes release on
  locally built images, for the things only a cluster can show: the ingress, a
  session cookie shared by four hostnames under one parent domain, per-user
  volumes, and the layout migration on a real disk.

Neither publishes anything.

## Upgrading

`CONTENT_RETENTION_SWEEP_HOURS` is gone: it was read from the environment and
used nowhere. Retention runs on the existing housekeeping tick.

Migration 12 adds an index and is applied on first start. Nothing else in the
database changes.
